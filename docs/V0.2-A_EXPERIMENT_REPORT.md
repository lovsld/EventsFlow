## 实验 3：通用性

### 3(a) 世界配置外置（行为保持型重构）

`ADJACENCY` 四份副本收敛为 `v02/world_config.py` 的单一定义；
地点/邻接/景物/关键物品初始态/环境事件集中为 `DEFAULT_WORLD`
数据；WorldEngine 与 Resolver 改为读配置，搜查/展示改为按物品
客观位置/持有者的数据驱动判定（酒馆世界下与旧逻辑逐项等价）。
**验收：在 Phase 3 新规范轨迹上比重构前后 world_log —— 逐字
一致（md5 均为 `035483fae5faf3da6786c6cd42f6dc26`），通过。**

### 3(b) 变体场景（纯数据，零决策代码改动）

新场景「失踪的仓库钥匙」：`characters_variant/`（保管员老赵 /
寄货客商沈行舟 / 学徒小六，全新背景、目标、性格、私人知识）+
`scenarios/warehouse_key_world.json`（新景物、新关键物品
warehouse_key：客观上在后屋，持有者登记为保管员；新冲突事实：
钥匙今晨不见了——可被搜查证实）。地点名沿用既有五处（原因见
已知限制）。rule 模式 seed 42 跑 24 tick：
`runs_v02/variant_warehouse_key_seed42`。

结果：84 事件、72 决策、0 错误、72 条预测全落盘；事件类型
observe 40 / move 14 / listen 11 / ambient 11 / speak 3 / wait 4。

| 检查项 | 判定 | 证据 |
|---|---|---|
| 引擎层可跑 | ✓ | 世界/解决/投递/调度/持久化/检查点/叙事在全套新数据上无改动运行 |
| 因果链可追溯 | ✓ | 72/72 决策有 prediction 与 DB 链记录 |
| 局部认知 | ✓ | 三人终局信念恰为各自私人知识，一条不多；钥匙 objective seen_by 全程只有 keeper |
| 行为由目标驱动 | ✗ | 三人行为同质（谨慎→观察主导），保管员从不去后屋找钥匙、客商从不打听提货——rule 候选按酒馆角色 id/断言分支，新角色无对应候选 |
| 计划持续性 | 未触发 | 无任何计划被设定（设计划的解释路径与角色候选在变体中都不触发），该项无样本 |
| 合理互动 | 部分 | 有移动聚集与 3 次发言，但无任何围绕冲突（钥匙/提货）的实质互动 |

**判定：通用性部分成立。** 成立的部分是架构与数据层：世界、
感知、调度、记忆、信念证据、持久化、实验工具全部与剧本无关，
换场景零决策代码改动即可运行且认知隔离严格。未成立的部分是
决策内容层：rule provider 的目标导向候选与 `agent._interpret`
的断言解释表是酒馆剧本专属，变体角色因此「活着但不办事」。
这与 Phase 1 审查的事前判断一致，且边界现在有实证定位。

## 仅设计未实现

- 目标的 deadline 字段只有数据位，没有任何到期语义（不触发
  任何行为）；目标权重运行中不变（priority 静态）。
- 替换门控的「target 离开」维度：计划无 target 字段，未实现
  （以 critical/普通信息类实现门控）。
- LLM 轨迹的延迟与 JSON 修复率只有从新 run 起才有数（历史
  artefact 不补造）。

## 已知限制

1. **决策内容层与酒馆剧本绑定**（实验 3b 实证）：rule provider
   候选按角色 id/断言分支；`_interpret` 是酒馆断言表；发现物品
   的计划分支与 context_builder 的 show 可用性按 anonymous_letter
   写死。变体场景中这些部分不覆盖——按任务书纪律，未为变体往
   `_interpret` 添加任何新剧情规则。
2. **地点改名被两处硬编码挡住**：context_builder 只在 back_room
   提供 search、agent 发现分支针对 back_room 的信件；变体因此
   沿用五个地点名（拓扑与景物已可自由改）。
3. 目标完成率在酒馆 rule 轨迹为 0.0：计划标签与目标 key 的对齐
   只在老板身上成立，且计划鲜少在 20 tick 内走完（机制问题之外
   的剧本对齐问题）。
4. Store 打开旧 run 的 DB 会按当前 schema 补建缺失表——分析旧
   artefact 必须用副本（实验 2 已如此操作）。
5. honesty 人格维无读取点（未生效）；give/take 仍是占位动词
   （无转移语义，按不采纳决定保持）。

## 与 V0.1 的实际改进

V0.1 是三进程 + 文件队列的最小独立性证明：规则决策、无 LLM、
信念是单标签三档、无目标/计划运行时、无审计链。V0.2（含 A）
在此之上：单进程 asyncio 事件驱动 + 统一调度提交；真实多后端
LLM 接入（Gemini/DeepSeek/Kimi/Qwen/OpenAI）且 rule 模式零依赖
可跑；信念证据化且任何变化可溯源；预测—误差—信念的认知闭环
落盘可复原；计划有状态机（含 blocked）与承诺门控；目标成为
结构化运行时对象；实验工具有种子组、反事实与一致性审计；
中断可续跑、额度可等待。独立性约束（私有记忆、局部感知、世界
唯一提交、叙事只叙已发生事实）全程未放松。

## V0.2-B 建议

1. **决策内容层数据化**：把 rule provider 的候选与 _interpret
   断言表抽成场景数据（候选模板 + 断言→信念/计划的映射表随
   场景目录走），这是通用性从「部分成立」走向「成立」的唯一
   剩余大项；做完后用同一变体场景复测五项检查。
2. 地点语义去硬编码：search 可用性改为「该地点有可搜查景物/
   物品」的配置判定，发现分支按 world_config 的物品定义泛化。
3. 计划标签与目标 key 对齐：rule 候选的计划标签改用角色目标
   key（或显式 plan→goal 映射），让目标生命周期与完成率在
   酒馆轨迹里真正可测。
4. 延迟与 repair 计数已落盘新 run；可考虑给 DecisionRow 补
   latency 列，让后续 LLM 实验直接可算。
5. goal deadline 语义（到期提醒/降级）与 blocked 计划的自动
   恢复策略（重试上限后降级目标）可按需再议——本轮均只做到
   记录与状态，不引入新行为。
