## 2. §9.2 待核项结论（actors 语义）

遍历全部 rule 模式 run 的 1,220 个带文本言语事件：文本前缀人名与
`actors[0]` 的 profile 名 **1220/1220 一致**，且言语事件 actors
恒 ≥ 2 人。故定版：`actors[0]` = 说话人、`actors[1]` = 受话人，
Extractor 只用 actors 字段、永不解析文本前缀（LLM 模式 run 的文本
是自由文体，前缀约定不成立——但 actors 语义由引擎保证，与文本
无关）。

## 4. 拓扑注记（与金标准预期形态的差异，非判据差异）

诊所的两条主题链（patient / restock）最终并成一条 19 事件的主线，
并线路径是**医生的搜查序列**（E0002→E0049→E0070，E7 边）——医生
确实是两条链的枢纽，且终局报告 §4 本就把诊所视为一条含五环的主
链。金标准的实质判据（报断、断点、无成功误读）全部成立；并线不
改变任何判据方向。酒馆市长线判 closed 的口径是设计 §5.3 的结构
定义（发现被发声 + 提问在链级获答），**不等于剧情已解决**——信的
内容始终只是暗示与否认，Writer 阶段不得把它写成水落石出（此约束
记入 N3 输入说明）。

## 5. 实施裁量五项（请 Hu 追认）

| # | 裁量 | 理由与证据 |
|---|---|---|
| 1 | **E2 行动分句收紧**：只认「assert 立场的言语事件 → 其受话人（actors[1]）的其后首次搜查」 | 设计原文只说「被 A 接收」。初版按任意接收者连边时，阿贵（旁听者）搜灯被并入主线，违反金标准；且 inquire 按涌现层契约不携带信念，被问者无从「受信息驱动」。收紧后三金标准全过 |
| 2 | **新增 E7 搜查序列边**：同一角色相邻两次搜查连边 | 设计边表无此边，但 §5.5 的灯塔金标准链（断言→搜查→搜得→回报）没有行动序列桥就不可达。E7 只连同人相邻搜查（全验证集仅 5 条），语义是「同一次努力的延续」 |
| 3 | **B2（传递中断）不作断裂判据** | 初版 B2 对每个「终点型接收者」（本就只需知道、不需要转述的人，如酒馆老板收到商业提案）全部触发，三 run 每条线都被判 broken——判据无区分度。诊所的断裂由 B3（搜查落空）完整捕获。B2 已从状态判定中移除，代码内留注记 |
| 4 | **E2 言语分句改最近源归因**：每条「接收后发言」只连最近的一条来源 | 初版把某人发言前收到的每一条同题言语都连成因果边（酒馆单 run 64 条边、商人的一次发言挂 12 条入边），是过度归因。改后酒馆边数 64→40，每条入边可指认为最近触发 |
| 5 | **E4 言语分句收紧**：只认「发现者本人其后以 assert 发声该信念」 | 初版把发现连到任何人其后的同题言语，连出「医生找到入院表→护工提问」这类他人+提问的误边（3 条）。收紧后 5 条 E4 边全部为发现者本人断言（E0008→E0022、E0044→E0080 等），逐条正确 |

五项均为「设计文本落到数据上才暴露的口径问题」，与 V0.2-C 实施期
的裁量同性质：已在代码注记与本报告双登记，设计稿 §10 修订记录
已追加一行待追认。若 Hu 不追认其中任何一项，该项回滚并重跑验收。
