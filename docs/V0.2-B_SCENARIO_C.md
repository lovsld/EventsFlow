## 1. 场景与运行

**场景 C：诊所夜班**（`scenarios/scenario_c_clinic.json` +
`characters_scenario_c/`）。夜班护士林小满私下知道退烧药见底
（fever_med_low, 0.95），值班医生沈默私下知道今夜将收治高烧
病人（fever_patient_coming, 1.0），护工吴大勇只知道一件无关
私事（药房窗扣坏了）。护士的补药目标 restock_medicine 以
「得知病人要来」为激活条件（完成依赖跨角色信息流动之一）；
医生的 ensure_readiness 以「得知补药完成」为成功条件（依赖
之二）。地点图为 4 环 + 1 叶（度数序列 3,2,2,2,1，含环），与
酒馆/仓库的树形图 (3,2,1,1,1) 不同构。物品 fever_medicine
（药房，on_found=acquire）与 admission_form（值班室，
on_found=inspect，reveals fever_patient_coming 0.9）均为新造。

运行：rule 模式，seed 42 与 seed 7 各 24 ticks，另有 2-tick
冒烟（输出在 /tmp，未入 runs_v02）。

## 2. 实际发生了什么（两颗种子高度一致）

- **承载信息的 assert 言语一次都没有发生。** 两场合计 48 个
  tick、144 次决策中，出现的言语事件只有：护工反复 ask
  patient_inquire（13/12 次）、医生反复 ask restock_inquire
  （7/6 次）、护士两次 speak denial。除此之外没有 greeting、
  smalltalk，更没有 patient_notice、med_low_report、
  restock_report 中的任何一个。
- **医生从未说出 patient_notice。** 它进入医生候选 top-5 共
  4 次（seed42 的 candidate_scores 落盘可查），从未被选中；
  医生唯一一次 speak 类失败是 restock_inquire 的 target_left。
  更关键的是，其专为「发出通知」而设的目标 brief_nurse 在
  **两场都在 tick 0 即被暂停**（goal_changes: goal_paused,
  reason="plan pursuit switched to ensure_readiness")，此后
  24 tick 内从未恢复。
- **机会并不缺。** seed42 中医生与护士 t3 起就在 yard 同场
  开 session，之后多次三人同场。医生面对护工「有病人要来吗」
  的当面询问（t5 起反复），回应方式是反问 restock_inquire——
  掌握答案的人始终没有给出答案。
- **没有任何人 search 过任何地点**（两场 search 事件 = 0；
  candidate_scores 的 top-5 中 search 出现 0 次）。**没有任何
  人 work 过**（work 事件 = 0，尽管三人的 routine 都是 work，
  finish_chart 的成功条件也包含 work）。护士 24 tick 中 move
  了 20 次（两场皆然），在五处地点间持续游走，seed42 终局她
  人在 pharmacy——站在药房里，却没有搜查。
- **目标终局（两场相同）**：restock_medicine 与
  prepare_stretcher 全程 inactive（从未激活）；brief_nurse
  paused；其余 active 但 progress 恒 0（护士 finish_chart 的
  progress 随她路过 oncall 在 0↔0.5 间闪烁，见 §5 缺口 6）。
  **全场目标完成数 = 0，激活数 = 0，失败数 = 0。**
- **唯一真正流动的「信息」是负面的**：护士在 t13/t14 对医生
  的 restock_inquire 回以 denial，医生产生推断信念
  conceals:nurse_lin = 0.8（两场一致，belief_changes
  cause=interpretation）——矛盾推断通道在工作，但它流动的
  是「她在隐瞒」，不是任何一项目标所需的信息。此外医生因
  一次 target_present_miss 预测误差对护士信任 0.3→0.25。

## 4. 行为分化与因果链核查

表面分布可区分（move 主导的护士、ask 主导的护工、observe
主导的医生），但按预注册标准，**分化不成立**：三人的行为
各自锁死在一个低产出循环里——护工对着掌握答案的人反复问
同一句（重复惩罚在 candidate_scores 中可见在累积，t12 时
ask 的 repetition 已 0.44，却仍以 2.0337 对 2.0273 的发丝
差距压过 observe 当选），医生在「问补药」与「观察」之间
近乎掷币，护士无目标牵引地全场游走。设计因果链的五环
（医生断言 → 护士激活 → 搜药获得 → 护士报告 → 医生确认）
**第一环即断裂，后四环无从谈起**。这与仓库场景 B 的链条
形成对照：B 的第一环是「私人知识直接激活 + 搜查」，不依赖
任何人开口；C 故意把第一环放在「跨角色断言」上，而断言恰
是当前候选机制下最弱的一环。

## 5. 契约缺口清单（写数据时逐一撞到，按重要性排序）

1. **没有任何契约手段能让「主动断言」可靠发生。** claims 只
   定义了断言的资格（speaker_belief / min_confidence），契约
   不说明一个知道答案的 Agent 在被询问时会选择 assert 而非
   反问或沉默；event_occurred{claim} 型目标是唯一的「职责」
   杠杆，却会被计划追逐的暂停规则在 tick 0 静默压过（见缺
   口 2）。本场景的全部信息流设计都建立在这个未文档化的
   行为假设上，第一环因此落空。这是本次评测最重要的发现。
2. **目标暂停规则对数据作者不可见且无数据侧制衡。** 架构
   文档只说「被另一目标的关联计划顶替 → paused」，作者无从
   预知哪个目标 tick 0 就会被暂停、暂停后靠什么恢复（本例
   24 tick 未恢复）；契约也没有「不可暂停 / 优先级下限 /
   轮换公平」之类的数据字段可供保护关键目标。
3. **testimony 可靠度调制公式缺失（预注册风险 R1 坐实）。**
   base_reliability 经说话者信任调制后的实际置信度无公式、
   无示例数值，作者给目标设激活线（0.4）与完成线（0.65）
   时只能盲猜。本场景中该缺口未及实测（断言根本没发生），
   但它意味着任何依赖证言阈值的目标设计都无法在纸面验证。
4. **search 候选的产生条件对作者不透明。** 护士的目标未激
   活固然是主因，但全场 144 次决策的 top-5 候选里 search
   出现 0 次、且护士在 seed42 终局身处 pharmacy 也未搜查——
   作者从契约无法得知：search 候选究竟由什么触发（目标叶？
   计划步？在场可搜风景？），也就无法设计「让某人去搜某
   处」的目标，只能照抄仓库样例的形状祈祷它复现。
5. **顶替/会话机制（session、interrupted、speak_failed）不
   在契约内。** 事件流里言语以 session 组织、ask 可被
   interrupted、speak 可因 target_left 失败——作者写场景时
   无法预知「两人同场」与「话说出口」之间还隔着会话层，
   也无法解释为何当面询问会石沉大海。
6. **agent_at_location 叶是瞬时量、非闩锁，progress 会倒退。**
   finish_chart 的 progress 随护士进出 oncall 在 0↔0.5 间反
   复横跳（goal_changes 留下 4 条来回记录）。契约把 progress
   定义为「条件满足度」却未提醒位置叶不累计；「到某地做某
   事」型目标（仓库样例的 apprentice 目标同构）天然脆弱，
   作者无从得知该改用 event_occurred 组合还是接受闪烁。
7. **conceals:<agent> 信念的键格式与强度不在契约内。** 它由
   denial 的矛盾推断产生（本例恒为 0.8），是运行后从产物里
   反查到的；作者在写目标条件时无法预先引用这类推断信念，
   等于一整类「识破隐瞒」目标在数据层不可设计。
8. **无持有者物品（公共物品）如何表达不明确。** 两个样例
   的物品都有注册 holder；holder 可否为 null、seen_by 为
   空时物品是否仍可被搜到，契约未言。本场景被迫把
   fever_medicine 的 holder 注册给尚未取到它的护士（语义上
   是「责任归属」而非「持有」），属于照样例类推的将就。
9. **priority_rules 的 when/delta/once 只有一行描述。** 我按
   「条件 dict」试写并通过了加载，但两场中该规则（护工
   keep_gate，条件为得知病人要来）因条件本身从未满足而无
   从验证其是否真的生效、无 priority_change 记录可查——
   格式靠猜、效果靠等，是半条契约。
10. **「谁持有某物」的揭示路径对作者半透明。** fever_medicine
    的 reveals 给「找到者」写 fever_medicine_restocked 信念，
    是 restock_report 的 speaker_belief 前提——这条「物品
    reveals → 持有者自知 → 可对外断言」的链条只能由酒馆
    信件的 reveals 样例类推，契约没有一个完整走通的言语
    报告类样例可抄（仓库场景的物品 reveals 为空）。

## 6. 最终判定

**场景 C 通用性：不成立**（按预注册判定标准）。

依据（一句话）：两颗种子、48 tick、144 次决策中，承载跨
角色信息的 assert 言语一次都没有被选中，目标链第一环即
断裂——零目标激活、零目标完成、零次搜查，信息只以「她在
隐瞒」的推断形式负向流动了一次。

须同时记录的另一面（不改变判定，但界定失败的位置）：框架
层是通的——全新地点图（带环）、新角色、新物品、新命题纯
靠数据一次加载通过，两场零错误跑满；目标暂停/进度、矛盾
推断、会话、候选评分落盘等机制都在新场景里照常运转。失
败不在「场景装不进来」，而在**决策内容层**：通用候选生成
能稳定地产出询问与观察，却产不出（或选不出）主动断言与
定点搜查——与 V0.2-A 实验 3b「行为同质化」相比，这次的形
态是「行为分化了，但分化成三种各自锁死的低产出循环」。
按预注册口径，链条部分闭合（如激活发生）即可记部分成立；
本场景中激活从未发生，故不记部分成立。

给后续版本的建议（仅基于本评测证据）：① 把「被询问且持
有答案时的 assert 响应」做成与 inquire 对等的通用候选来
源，并在契约中写明；② 目标暂停须有数据侧可见性（落盘理
由已有，建议在角色状态/文档中给出恢复条件清单）；③ 在
契约中补 testimony 调制公式与至少一个数值示例；④ 给出
search 候选触发条件的明确文档。
