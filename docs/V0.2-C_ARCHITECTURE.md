## 1. 总原则（C 轮新增/重申）

1. **四层完成语义仍严格分离**（Action / Step / Plan /
   Goal），C 轮全部机制只在各自层内工作：调度器只写
   pursuit 与暂停簿记，步评估只判步，GoalEvaluator 仍是
   目标状态的唯一写者。
2. **生成是义务、选择不是**：C2 起，应答/断言候选的
   *生成*由契约保证（知道就必须生成 answer 候选），但
   *选中*仍由统一效用竞争决定——设计 §3.1 明确否决过
   「义务候选强制胜出」的第二通道（见停放项 P-C2-1）。
3. **未送达不算发生**（修复轮）：Agent 自身行动记录中
   世界层 `ok=False` 者，不计入事件史求值、也不能解除
   披露职责。客观真实性优先于簿记便利。
4. **一切新动力学先校准后定版**：C1 效用系数与 C2 应答
   披露系数均由预注册校准实验定版（过程全录于实施
   报告），不许手拍常数；定版后跨轮不得漂移。

## 3. 决策动力学（C 轮四组机制）

### 3.1 Goal Scheduler（C1）

- 输入：本角色目标集、各自 progress（单调化后）、依赖
  图、暂停簿记；输出：本 tick 的 pursuit 与暂停/恢复
  建议。效用 = 基础优先级 + `dep ×` 依赖牵引（被依赖者
  牵引依赖者的 pursuit，如诊所 ensure→brief 拉动
  0.85 + 0.6×1.0 = 1.45 > 1.0 的翻转即由此式）+
  `wait ×` 等待老化 − 切换惩罚，挑战者须越过
  `switch_margin` 滞后门槛且现任未在 `min_dwell` 保护
  窗内，才允许换 pursuit。
- 定版常数（18 组预注册校准的胜者，非手拍）：
  `dep=0.4`、`wait=0.15`（wait_scale=10）、`switch=0.2`、
  `switch_margin=0.10`、`min_dwell=2`、
  `max_pause_ticks=8`（全局缺省，可被目标自身
  scheduling 字段覆盖）。
- 暂停双层制：目标层暂停是**政策决定**（pausable /
  priority_floor / max_pause_ticks /
  starvation_protection 四字段），争用先由计划层
  suspend 吸收；被 depends_on 门控（从未参与争用）的
  目标不记暂停（防假饥饿，C1 校准期实证修复）。
- Goal Progress 单调化：progress 只升不降，完成仍按
  当前条件满足判定（Hu 决策 #2）。

### 3.2 Communication Generator（C2）

- **待答队列**：被点名提问入队（条目带 `via` 与提问者、
  命题），TTL 3 tick，过期写审计行，不再单槽静默丢弃。
- **Answer 义务**：对队列中 ask 条目，若本角色持有可
  回答的信念，answer 候选**必须生成**（义务在生成
  层）；定价走受方口径：info 按 §3.3 字面 flat 1.0
  （点名问过即满值），披露系数
  `ANSWER_DISCLOSURE_COEF=2.6`（预注册校准定版；高于
  主动披露的 1.6——flat 受方计价先行吃掉了折扣空间，
  此反转如实记录于实施报告，未为叙事好看而调）。
- **Assert 定价**：按估计的**受方无知**计价（感知史
  近似：被问过 = 1 / 已断言过 = 0 / 无记录 = 0.5，
  近似口径已声明）；断言对象、时机与是否选中仍由
  统一效用决定。
- **披露职责（Disclosure Duties）**：写在角色数据里
  （命题、对象、urgency、触发信念阈值），运行时分
  applicable（已武装）与 undelivered（已武装、对象
  不在场、未真正告知）两态；「已告知」判定经
  `_told_target` 且带 ok 门控（修复轮）。
- 信息隔离不变：定价只用本角色感知史与自身信念，
  不读他人状态。

### 3.3 统一 Information Value（C3）

`v02/info_value.py` 是唯一定义点，各行动类型的 IV
实例化：ask 沿 B 的 1−conf；answer flat 1.0；assert =
受方无知估计 × relevance；disclose = 职责 urgency；
search = 1 − searched_certainty（SEARCHED_CERTAINTY
=0.9；已搜集合由 `searched_places` 从既有状态派生，
含搜空地点）；observe/listen = SENSOR_IV 0.3（传感器
常数，明示）；move 腿 ×0.8。基线探索：本 tick 无目标/
计划候选且无点名待答义务时，未搜可搜地点生成
baseline search/move 候选（info = curiosity × 0.2）；
持有型叶（object_possession{holder=他人}）在 holds
信念 <0.9 且物可搜时增补 search_route。

### 3.4 Plan 粒度与 replan 门槛（C4）

- **步履约每 receive 判定**：当前活动步在每次 receive
  （行动结果与感知事件摄入后、目标评估前）被判定履
  约；多 tick 的问→答插曲因此能闭合步。失败计数保持
  与行动绑定（等待 receive 不计失败）。
- **局部性契约**：纯信念叶不得单独作步条件。
  rule 路径的 `synthesize_steps` 把信念叶步合成
  `evidence:` 步——`any[信念叶, 断言该命题的
  event_occurred 支, （有对应物体时）object_found
  支]`；LLM 侧同一契约写入共享的 `_JSON_CONTRACT`
  指引条款（仅指引，无新增运行时拒绝）。
- **失败规则 (c) 收窄**：`decisively_false()` 只认
  object_possession / object_at_location /
  object_found / agent_at_location 四类硬假叶；
  「信念尚未取得」从此只产生 not-yet-decidable，不再
  凑 blocked（诊所医生假阻塞病理由此消除）。
- **语义指纹与门槛**：叶签名归一化（agent 引用塌缩
  self/other、阈值按 0.25 分桶），步签名多重集
  Jaccard ≥ `SIMILARITY_THRESHOLD=0.8` 且
  context_digest（目标相关信念分桶 + 持有物 + 已发
  现物 + 派生已搜地点集 + 自身位置）不变时，新计划
  判为「同计划同世界」：replan 被门槛改派 suspend 并
  落盘 `replan_gated`；失败记忆 cap 8（FIFO）、同目
  标同 digest 命中 `GATE_SOFT_CAP=3` 后软顶暂停该目
  标的计划合成直至 digest 变化。digest 含已搜地点
  集，仓库式生产性 replan（搜过新地点后重提）不被
  误拦——仓库双 seed 实证。

### 3.5 传讯真实性契约（修复轮）

- `event_occurred` 求值并入自身动作史时跳过
  `ok is False` 的记录（无 ok 字段的旧记录照旧计
  入）；comm 的职责「已告知」判定同门。
- 叶新增可选 `stance` 谓词：记录须带匹配的言语行为
  类型戳（assert / inquire / deny 等，由 Claim 定义
  派生，感知事件与自身动作两条路径都打戳），无戳记
  录不能满足带 stance 要求的叶。数据借此可精确表
  达「断言已送达」而非「发生过任何言语事件」——诊
  所 brief_nurse 的成功叶使用 `stance: assert`，属
  契约的正当数据使用。

### 3.6 职责寻求（修复轮）

对每个 undelivered duty（职责已武装、具名对象不在
场、未真正告知），rule_provider 在 step 3a 生成朝
向该对象 **last-seen 位置**（本角色自身感知史）的
移动候选：info 取职责既有 IV，obligation 加成按
「持有可报告知识至今的等待 tick」计——无新常数。
只用自身状态推导，不读他人目标/信念。已知边界见
P-FIX-2（位置知识新鲜度）。

## 5. 作者契约（供 C5 独立测试方）

盲测场景作者只凭本文 + `docs/V0.2-B_ARCHITECTURE.md`
§3（数据契约）+ 仓库范例（`scenarios/warehouse_key_
world.json` + `characters_variant/`）写纯数据，不需要
也不应该读 `v02/` 源码。要点：

1. 场景 = 一个 scenario JSON（地点图、物品、claims、
   台词）+ 每角色一个目录（profile / goals 数据）。
2. 目标用条件叶声明激活/成功/失败；目标间依赖用
   depends_on（同角色）与 scheduling{} 表达；跨角色
   信息流靠 claims 与披露职责（profile 数据）驱动，
   不要指望任何代码替场景「安排剧情」。
3. 「某人已被告知 X」类成功条件：用带
   `stance: assert` 的 event_occurred 叶，或直接以
   本角色可感知的断言事件为据——提问（inquire）不
   携带信念，这是契约语义而非实现细节。
4. 计划步的条件会被每 receive 判定；把步条件写成
   「该步自身行动或其直接回应事件能改变的条件」
   （局部性契约），纯信念叶请与 event_occurred /
   object_found 组合为 any。
5. 冻结清单（实施报告「冻结清单」节）是判定代码是
   否被动过的唯一依据：跑前跑后各验一次哈希，任一
   不符则本轮盲测作废。
